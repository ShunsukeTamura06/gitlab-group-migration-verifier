GitLab Group Migrator - Windows かんたんスタート
================================================

必要なもの
----------
- Windows 10 または 11
- Python 3.11以上
- 移行元と移行先のGitLabへ接続できるネットワーク
- 移行元のAccess Token（api scope、対象GroupのOwner相当）
- 移行先のAccess Token（api scope、Group作成・Import権限）
- 組織から指定された移行申請、バックアップ、承認

配布物の確認
------------
このZIPは社内配布担当者から受領してください。
GitLab URL、社内CA、必要容量は設定済みなので、利用者には質問されません。
URLを質問された場合は公開汎用ZIPです。操作を中止して配布担当者へ連絡してください。

最初に確認すること
------------------
同梱の MIGRATION-SCOPE.md を読み、移行対象、自動確認対象、手動確認対象、
別途再設定する対象を移行責任者と確認してください。
このツールの実行成功だけでは、GitLab全データの移行完了にはなりません。

使い方
------
1. ZIP全体を右クリックし、「すべて展開」を選びます。
2. MIGRATION-SCOPE.md の内容を確認します。
3. 展開したフォルダーの「Start-GitLabMigration.cmd」をダブルクリックします。
4. 初回だけAccess Tokenを非表示入力し、保存するか選びます。
5. 画面の質問に答えます。
5. Group移行は最初にPilot、個人Project移行は最初に事前診断を選んでください。
6. 完了後、work\reports に作成されたレポートを責任者へ渡します。

Tokenについて
-------------
Tokenは入力時に画面へ表示されません。
「保存しますか」でEnterを押すと、現在のWindowsユーザーの
資格情報マネージャーへ保存され、次回から入力を省略します。
配布フォルダーや設定JSONへは保存されません。
共有Windowsアカウントでは保存せず、nを入力してください。

Tokenを変更・削除する場合
-------------------------
1. Clear-SavedTokens.cmdをダブルクリックします。
2. 削除完了後、Start-GitLabMigration.cmdを起動します。
3. 新しいTokenを入力し、必要ならもう一度保存します。

GitLab側でTokenを失効してもWindowsの保存値は自動削除されません。
Tokenをチャット、チケット、メール、スクリーンショットへ載せないでください。
移行実行者にGitLabインスタンス管理者権限は不要です。
既存の親Groupへ配置する場合は、そのGroupで新しいSubgroupを作成できる権限が必要です。
個人Project移行では、両Tokenがそれぞれ移行元・移行先の本人アカウントに
対応している必要があります。

個人Project移行の制約
---------------------
個人NamespaceへImportすると、IssueやMerge Request等の投稿者は
移行先アカウントへ集約され、後から再割り当てできません。
移行先に同じPathのProjectがある場合、そのProjectは上書きせず
内容を比較しないでスキップし、残りだけを移行します。

止めるべき場合
--------------
- 事前診断に「失敗」がある
- 警告について移行責任者の判断がない
- 本番前のPilot、バックアップ、変更凍結、切り戻し確認が終わっていない
- 途中でエラーになった（同じ操作をそのまま再実行しない）

個人Project移行の再開
---------------------
個人Project移行で途中エラーになった場合は、このフォルダーを削除せず、
Start-GitLabMigration.cmdをもう一度起動してください。
未完了Manifestが見つかると「続きから再開」を選べます。
完了済みProjectは再Importしません。

v1.3.0、v1.3.1、v1.3.2のいずれかからv1.3.3へ更新する場合は、旧フォルダーのworkフォルダー全体を
新しい展開フォルダーへコピーしてから起動してください。
